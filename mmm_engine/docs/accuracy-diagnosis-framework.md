# MMM 精度悪化 診断フレームワーク

作成日: 2026-06-25

---

## 概要

MMMの精度（R²・NRMSE・RSSD）が良くない場合の診断手順。  
「何が悪いか」を切り分けてから対処することで、無駄な試行錯誤を減らす。

---

## Step 1｜過学習 vs 説明力不足を切り分ける

**最初に確認するのはここ一点。**

```
NRMSE(holdout) / NRMSE(train) の比率

  > 2.0   → 過学習（ダミー過多・パラメータ過剰）
  1.2〜2.0 → 軽度の過学習 or ホールドアウト期間の異常
  ≒ 1.0   → 両方高い → 説明力不足（データ/特徴量の問題）
```

R² < 0.80 かつ 比率 ≒ 1.0 のとき → Step 2-⑤ に直行。

---

## Step 2｜原因パターンと着手優先順

| 優先 | 診断サイン | 原因 | 着手すること |
|:-:|:-|:-|:-|
| ① | NRMSE(hold)/train比 > 2 | ダミー変数過多 → 過学習 | patience引き下げ / ダミー上限削減 |
| ② | スパースch（ゼロ率80%超）が3本以上 | 係数の奪い合い・不安定化 | コントロール変数化 or 除外して再実行 |
| ③ | ベースライン比率 > 85% | 広告変動が少ない or 効果が構造的に小さい | データ期間延長 / 上流課題として整理 |
| ④ | RSSD > 0.30 | スペンド大chが係数ゼロ or 寄与逆転 | λプロファイル変更・多重共線性チェック |
| ⑤ | R² < 0.80（holdoutも低い） | 季節性・イベント等の未捕捉 | コントロール変数追加（祝日・競合フラグ等） |
| ⑥ | CPA毎回ブレる（ゼロ⇔大値） | スパース + 他chとの共線性 | 当該ch除外して安定度を確認 |

---

## Step 3｜診断フロー（判断ツリー）

```
精度が悪い（R²低 / NRMSEhigh / RSSDbig）
  │
  ├─① NRMSE(hold)/train比 > 2？
  │     YES → ダミー変数削減（patience or 上限引き下げ）
  │     NO  ↓
  │
  ├─② スパースch（ゼロ率80%超）が3本以上？
  │     YES → コントロール変数化 or 除外して再実行
  │     NO  ↓
  │
  ├─③ ベースライン比率 > 85%？
  │     YES → データ構造の問題。モデル改善より上流課題として整理
  │           （「このモデルで信頼できる範囲はここまで」と定義する）
  │     NO  ↓
  │
  ├─④ RSSD > 0.30？
  │     YES → λプロファイル変更 or 多重共線性チェック
  │     NO  ↓
  │
  └─⑤ R² < 0.80 かつ holdoutも低い？
        YES → コントロール変数追加（季節性・イベント・祝日フラグ）
```

## 各指標の目安値

| 指標 | ◎ 良好 | 〇 許容 | △ 注意 | × 要改善 |
|:-|:-:|:-:|:-:|:-:|
| R² | ≥ 0.93 | ≥ 0.85 | ≥ 0.80 | < 0.80 |
| NRMSE (train) | < 0.08 | < 0.10 | < 0.15 | ≥ 0.15 |
| NRMSE (holdout) | < 0.10 | < 0.15 | < 0.20 | ≥ 0.20 |
| RSSD | 0.10〜0.20 | ≤ 0.30 | ≤ 0.40 | > 0.40 |

## 対処法の選択肢

### スパースチャネルの扱い

| 方法 | やること | 向いているケース |
|:-|:-|:-|
| **コントロール変数化** | 0/1フラグとして投入（施策実施有無） | 施策日は把握できるが投入量が少ない |
| **除外** | チャネルごとモデルから取り除く | 有効データが5件未満で推定不能 |
| **そのまま維持** | 結果にゼロ判定が出ることを許容する | 他chへの影響が軽微と判断できる場合 |

### ダミー変数の調整

```python
# 現在の設定（patience=2 / 上限=n_train×5%）
auto_dummy_search(..., dummy_cap_pct=0.05, patience=2)

# 過学習がひどい場合 → patience=1 or dummy_cap_pct=0.03 に引き下げ
# 精度不足の場合   → target_r2=0.90 に引き上げ（ただし過学習注意）
```

### コントロール変数追加の候補

- 曜日フラグ（週次データでは不要）
- 祝日・連休フラグ
- 競合キャンペーン実施フラグ
- 自社オフライン施策フラグ（展示会・プレスリリース等）
- 外部環境変数（降水量・気温などがCVに影響する業種）

## 構造的な限界について

**スパース除外は「症状への対処」であり、根本治療ではない。**

最上流の問いは「そのクライアントの広告がCV変動にどれほど寄与できる構造か」。

- 施策が通年フラットに投下 → 変動少 → 帰属困難
- ベースライン（季節・SEO等）がCVを支配 → 広告の見た目の貢献が薄くなる

この場合、どれだけモデルを調整しても帰属比率の構造的な限界がある。  
クライアントに対しては「このモデルで信頼できるチャネルはここまで」という  
解釈の枠を設定することが実務的なゴールになる。
